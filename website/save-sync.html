Save Sync and Shizuku

Retro Toolbox · Android only · Save Sync is in alpha

The short version. Save Sync copies your game saves between your handhelds and phones, one app at a time, and keeps older copies so you can go back. Android does not let one app open another app's save folder. Shizuku is a free app that gives Retro Toolbox that access, without root. Without it (or root), Save Sync can show your list but cannot move any save.

What Save Sync is

Save Sync keeps game saves in step between your devices. Play on your handheld, then carry on from the same point on your phone.

  • Per app. You choose which apps sync: emulators and Android games. Each one has its own row.
  • One save at a time. An emulator keeps one save per game. Each of those gets its own line and its own button, so syncing one game never touches another.
  • You decide when. Nothing syncs on its own. Download a game's save before you play and upload it after.
  • With a history. Every save Save Sync replaces is kept first. See Versions, backups and history.

Open it from the main menu: Save Sync. It is only in the Android app.

How it works

The hub

The hub is the one place all your devices share. The first time you open Save Sync it asks Where should saves go? You pick one of two:

  • Google Drive (Sign in with Google). Saves go into a folder named Retro Toolbox Saves in your own Drive. Retro Toolbox can see only the files it puts there, nothing else in your Drive. This button only shows in builds that are registered with Google.
  • A folder (Use a folder). Saves go into a folder on the device, Retro Toolbox Saves in your storage by default. Retro Toolbox uploads nothing here: another app you choose, such as Syncthing or FolderSync, carries the folder between your devices. With a folder hub, "up to date" means up to date with what the folder holds right now.

You can switch later: tap the (i) on the Save Sync screen, then Change. Switching never touches your game folders.

The list of apps lives in the hub too. When a second device joins the same hub, it shows This hub already covers those apps and lists the ones installed there. Apps you add on one device reach the others.

Upload and download

Each row says what it needs and offers one button:

  • Needs upload, button Upload (a push): this device has a newer save than the hub. It is copied to the hub.
  • Needs download, button Download (a pull): another device pushed a newer save. It is copied into the game's folder here.
  • Up to date: nothing to do.

Close the game first. If the game is running, its row says Close the game first and upload and download wait. A download can also be refused when the recipe says the save needs a matching or newer version of the game than the one installed here.

Tap a row (or Check in its menu) to see what Save Sync found: whether the app is installed, where its saves are, and whether the copies in the hub are intact. Check changes nothing.

Versions, backups and history

Save Sync keeps more than the latest save, in three places:

  • Versions in the hub. Every upload is stored as a new version (the app calls it a "gen", short for generation), linked to the version it came from. The hub keeps the newest 20 versions of each save, plus any version that is still current.
  • A backup per device in the hub. Before a download replaces a save, the save that was here is uploaded to the hub as this device's backup. There is one backup per device for each save. Put it back with Restore a backup… in the row's menu (the three dots).
  • History on this device. Every save a download, restore or conflict choice replaces is copied first to RetroToolbox/SaveSync/history in your device storage. The newest 20 copies of each save are kept. You can reach them with any file manager.

Conflicts

A conflict is when two devices both changed the same save since they last synced. The row says Both sides changed since the last sync and offers Choose version.

You see each version side by side: the one On this device and the one from each other device, with its date and number of files. Tap Keep this on the one you want. The other one is not lost: the save it replaces is kept in this device's history first. The version you keep is uploaded as a new version, which settles the conflict on every device without asking again.

Recipes

A recipe tells Save Sync where an app keeps its saves, which files are the save and which belong to one device only (settings, the app's own backups, files it is still writing).

  • Published recipes. Recipes for apps such as Stardew Valley, Hollow Knight, Minecraft and the Switch emulators Eden and yuzu are published in the project's GitHub repository, in the save_recipes folder. Save Sync downloads the ones it needs. You can point it elsewhere in Settings, Recipes source.
  • Adding an app. Tap Add an app. Every installed app with a launcher icon is listed. Each one says Recipe available (with verified when it has been checked), Recipe ready, Already added, or No recipe yet. Tick the ones you want and tap Add.
  • Describing an app yourself. For an app with no recipe, hold its icon. Save Sync shows you the app's real save folder and asks three things: the folder, what counts as one save, and what should travel. Save recipe keeps it on this device and adds the app. The recipe then travels to your other devices through the hub. This step needs Shizuku or root, because it looks inside the app's folder.
  • Confirming. A recipe that has not been verified asks once, Are these the saves?, showing the files it found. Tap Use this place if they look right.

Shizuku: why Save Sync asks for it

What Shizuku is

Shizuku is a free, open-source app by RikkaApps. It lets other apps run commands with the same access as ADB, the shell you get when you connect a phone to a computer for debugging. It does this without root. You start it yourself, and each app has to ask your permission before it can use it.

Why Retro Toolbox needs it

Most games and emulators keep their saves in their own folder, Android/data/<app>. Since Android 11, normal apps cannot open other apps' folders there, even with All files access. The shell can. So Save Sync reaches those folders through Shizuku.

Save Sync can use one of three access modes. The screen tells you which one it has:

  • Shizuku (shell). Shizuku started through wireless debugging. Reaches Android/data. This is what most people use.
  • Root. Shizuku started on a rooted device, or, in the version of the app from GitHub releases, root through su directly. Root also reaches saves an app keeps in its private internal storage (/data/data), which the shell cannot open. The Google Play version does not call su itself; on a rooted device it gets root through Shizuku started with root.
  • None. No access to game folders.

What works without it: choosing the hub, signing in to Google Drive, reading the hub, seeing which apps it covers, and adding apps from the catalog. Nothing can be uploaded, downloaded, checked or described, because all of that reads or writes the game's folder.

What Retro Toolbox does with it

Only Save Sync uses Shizuku, and only while you use Save Sync. Each command is sent on its own to a small service that Shizuku starts for Retro Toolbox. The commands are:

  • List, read, hash, copy, move and remove save files, and create a save folder (sh to list a folder, test, stat, find, sha256sum, cp, mv, rm, chmod, mkdir, rmdir). With root it also sets a new file's owner to match its folder (chown).
  • Check whether the game is running, so a save is never replaced under it (pidof).
  • Check whether the app is installed and which version it is (pm path, dumpsys package).

Every path is checked before a command sees it. A command may only touch the folders of the app being synced (Android/data/<app> and /data/data/<app>) and Retro Toolbox's own RetroToolbox/SaveSync folder. Anything else is refused.

What it does not do

  • It does not touch any folder outside the ones above.
  • It does not install or remove apps, or change system settings.
  • It is not used by any other part of Retro Toolbox.
  • It sends nothing anywhere. Saves go only to the hub you chose.
  • It does not root your device. Shizuku only has root if you started Shizuku with root.

Set up Shizuku, step by step

Shizuku's own guide has pictures and more detail: shizuku.rikka.app/guide/setup.

  1. Install Shizuku from Google Play or its GitHub releases. Retro Toolbox needs Shizuku 11 or newer.
  2. Start Shizuku. Pick one:
    • Wireless debugging (Android 11 and later, no computer). Turn on Developer options, then Wireless debugging, while connected to Wi-Fi. In Shizuku, start pairing. In Wireless debugging, tap Pair device with pairing code, and type the code into Shizuku's notification. Then tap Start in Shizuku. You only pair once.
    • Root. On a rooted device, tap Start in Shizuku and allow the root request.
    • A computer. On Android 10 and older, start it from a computer with ADB, as the guide explains.
  3. Open Retro Toolbox, then Save Sync. If Shizuku is not running yet, you see No access to game folders and Start Shizuku (wireless debugging, or root), then come back and refresh. Tap Retry.
  4. Grant access. The card now says Shizuku is running. Allow Retro Toolbox to use it. Tap Grant Shizuku access. Shizuku asks whether to allow Retro Toolbox. Allow it.
  5. Check it worked. The card goes away, and the (i) on the Save Sync screen shows Access: Shizuku (shell). If Shizuku runs with root, it shows Access: root. Tap any row: the Check list shows Access with Shizuku (shell) or root.

After a reboot. Shizuku started with wireless debugging (or a computer) stops when the device restarts. Start it again in Shizuku before you sync. You do not need to pair or grant access again. Newer Shizuku versions can start by themselves on some devices; see Shizuku's settings and guide.

Troubleshooting

Shizuku stopped after a reboot

Save Sync shows No access to game folders again. Open Shizuku, make sure you are on Wi-Fi with Wireless debugging on, and tap Start. If it will not start, turn Wireless debugging off and on again. Then go back to Save Sync and tap Retry or the refresh button at the top.

Permission denied

If you tapped Deny in Shizuku's prompt, the card stays on Shizuku is running. Allow Retro Toolbox to use it. Tap Grant Shizuku access again. If no prompt appears, open the Shizuku app, find Retro Toolbox in its list of apps and allow it there, then refresh Save Sync.

The button only shows while Shizuku is running. If you see Retry instead, Shizuku is not running: start it first.

An app is not listed

  • Your apps are all under "Not on this device". Without access, Save Sync cannot look at what is installed, so every app the hub covers is folded into Not on this device. Set up Shizuku, then refresh.
  • An app is missing from Add an app. The list shows apps with a launcher icon only. Search by name or package name.
  • An app says "No recipe yet". You can still add it, and it waits for a recipe. Or hold its icon to describe it yourself.
  • A row says "Open the app once so it makes its save folder." Start the game once and save, then refresh.
  • A row says "Saves live in a folder only root can open. This device isn't rooted." That app keeps its saves in internal storage, which only root can reach. Shizuku started with wireless debugging cannot open it.

FAQ

Is my Google Drive data private?

Save Sync asks Google only for the drive.file permission. With it, Retro Toolbox can see and change only the files and folders it created itself, and nothing else in your Drive. The saves, and small files that list your devices and the games they sync, go straight from your device to your own Drive. Nothing reaches the developer. See the privacy policy.

What happens on a conflict?

Nothing is overwritten on its own. The row asks you to Choose version, and whichever you keep, the other is kept in this device's history first. See Conflicts.

Can I undo a sync?

Yes. After a download, use Restore a backup… in the row's menu to put back the save that was here. Older copies are in RetroToolbox/SaveSync/history on the device, and the hub keeps the last 20 versions of each save. See Versions, backups and history.

Do I need Shizuku if my device is rooted?

Not with the version from GitHub releases: it uses root directly when su is available. The Google Play version needs Shizuku, which you can start with root.
